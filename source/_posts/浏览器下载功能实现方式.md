## 浏览器常用下载方法

最近在整理项目的时候，发现一个问题：

我项目的导出功能是发送一个请求，由`Service Worker`拦截这个请求，并且代为下载并实时解密，并用流式 `Response` 返回。浏览器的下载器直接消费这个响应。

但是因为我使用了`FDM`下载器，浏览器插件会捕获下载请求并且发送给下载器代为下载。而下载器中没有我的 SW，因此会下载失败，返回一个网页

![image\.png](../images/7/image%201.png)

但同时存在一个问题，FDM并不是所有的下载都会捕获，在部分情况下，比如Telegram下载视频，比如使用捕捉器下载B站视频，就是直接走的浏览器下载通道，而不是走的FDM下载通道

![image\.png](../images/7/image%202.png)

那么FDM的链接捕获是由什么界定的呢？是网址黑名单，还是通过浏览器请求下载的不同方式？

查询资料得：在浏览器请求进行下载，可以分为以下几个方法：

### href

```Go

(() => {
  const url = 'https://example.com'
  const a = document.createElement("a");
  a.href = url;
  a.download = "testfile.zip";

  document.body.appendChild(a);
  a.click();
  a.remove();
})();
```

```Go
window.location.href = 'https://example.com'
```

### windows\.open

```Go

window.open(
  "https://example.com",
  "_blank"
);
```

浏览器下载

### blob

```JavaScript

(async () => {
  const url = "https://example.com";

  const response = await fetch(url);
  const blob = await response.blob();
  const objectUrl = URL.createObjectURL(blob);

  const a = document.createElement("a");
  a.href = objectUrl;
  a.download = "xbackup20260306.zip";
  a.click();

  setTimeout(() => URL.revokeObjectURL(objectUrl), 60000);
})();
```

通过JavaScript为已经在本地的文件对象创建一个临时链接，并访问这个临时链接下载

### File System Access API

```JavaScript

(async () => {
  const handle = await showSaveFilePicker({
    suggestedName: "stream-test.bin"
  });
  const writable = await handle.createWritable();

  const stream = new ReadableStream({
    start(controller) {
      for (let i = 0; i < 10; i++) {
        controller.enqueue(new Uint8Array(1024 * 1024));
      }
      controller.close();
    }
  });

  await stream.pipeTo(writable);
  console.log("10 MB 流式写入完成");
})();
```

这种方法是不走下载通道，而是JS直接尝试保存在用户电脑上
