编程部分程序默认位置的修改

发表于2026-06-25|更新于2026-09-18
|浏览量:

因为长时间没管理空间，各种环境依赖都往C盘装。现在已经积重难返（强迫症犯了），再加上当前使用的 win11 24H2 一堆 bug (比如开机时键盘重复速度被随机隐性调到最低等)，经过思考决定全盘格掉重装

因为我有点轻微的强迫症，所以就想要将所有的编程相关的放在一起，但是不同编程工具的默认行为不一样。各种默认缓存、中央仓库等……因此整理文档，以供未来再发癫重装的时候快速配置环境

当你看到这行字的时候说明文档还没完工

JAVA

MAVEN

maven的默认仓库放在C盘下面。管理仓库位置需要手动编辑 maven 的配置文件

虽然在这里设置了，但一个不注意，Maven wrapper自动下载一个新的把配置覆盖了，就又放到C盘去了

虽然 MAEVN 没有一个类似于 GRADLE_USER_HOME 的环境变量，但从 MAVEN 3.9+ 开始，可以使用 MAVEN_ARGS 环境变量在运行时自动附加参数

比如，将MAVEN_ARGS 环境变量的值指定为 -Dmaven.repo.local=path\to\maven-repository，在运行 mvn clean install 时是 mvn -Dmaven.repo.local=path\to\maven-repository clean install 的效果

若 MAVEN 版本低于 3.9+，可以使用 MAVEN_OPTS 环境变量，可以实现相似的效果

GRADLE

gradle 和 maven 类似，也是有本地的仓库。但它与 maven 不同的是，Gradle 可以通过环境变量规定仓库位置

GRADLE_HOME 指定 Gradle 存储其全局配置属性、初始化脚本、缓存、日志文件等的 GRADLE_USER_HOME 目录。
如果未设置，则默认为 USER_HOME/.gradle。
GRADLE_USER_HOME Gradle 的安装目录。
可用于指定本地 Gradle 版本，而不是使用 wrapper。
您可以将 GRADLE_HOME/bin 添加到您的 PATH 中，以用于特定应用程序和用例（例如测试 Gradle 的早期版本）。

PYTHON

pip

使用 pip install xxx 安装的依赖一般会默认存放到 python 的安装路径中，类似于 Python\Python313\Lib\site-packages 下

但是，pip 存在全局缓存的概念，用于避免重复下载。pip的全局缓存一般存放在%LocalAppData%\pip\Cache目录下，从pip版本 20.1 开始，pip可以通过环境变量 PIP_CACHE_DIR 指定全局缓存路径

uv

uv 是python的包管理与项目管理工具，其集成了python版本管理、虚拟环境管理、依赖安装、构建等功能

uv创建的虚拟环境会默认放在项目的根目录

在0.0.5版本后，uv引入了UV_CACHE_DIR环境变量管理uv全局缓存目录

在0.2.22版本后，uv引入了UV_PYTHON_INSTALL_DIR环境变量管理uv管理的python的安装目录

在0.2.16版本后，uv引入了UV_TOOL_DIR环境变量管理uv tool install指令常见的工具隔离环境

conda

go

可以使用GOPATH指定全局go二进制文件路径，第三方包缓存也会默认放在这里

还有类似于GOMODCACHE的环境变量，等会再继续写

Node.js

npm

npm 的默认全局缓存路径是%LocalAppData%\npm-cache，使用npm config get cache查看当前的缓存路径。

可以使用NPM_CONFIG_CACHE修改默认行为

pnpm

pnpm 使用pnpm store path查看当前缓存路径

使用PNPM_CONFIG_STORE_DIR修改默认仓库

bun

默认~/.bun/install/cache，查看bun pm cache

使用BUN_INSTALL_CACHE_DIR修改默认缓存

Android Studio

androiod studio的 android SDK 和虚拟机也会默认放在C盘，但与 Gradle 类似，可以通过环境变量约束

ANDROID_HOME 设置 SDK 安装目录的路径。设置后，该值通常不会更改，并且可以由同一台计算机上的多个用户共享。ANDROID_SDK_ROOT 也指向 SDK 安装目录，但已废弃。如果您继续使用它，Android Studio 和 Android Gradle 插件将检查旧变量和新变量是否一致。
ANDROID_USER_HOME 为 Android SDK 中包含的工具设置用户偏好设置目录的路径。 默认为 $HOME/.android/。
某些较旧的工具（例如 Android Studio 4.3 及更低版本）不会读取 ANDROID_USER_HOME。如需替换这些旧工具的用户偏好设置位置，请将 ANDROID_SDK_HOME 设置为要在其下创建 .android 目录的父目录。

前后端自动携带token校验
在之前的项目中，使用了smart-admin-v3，它的权限认证体系并非自己实现的，而是使用了 sa-token 框架。 在这个项目的开发过程中，我也查看了整个登录系统相关的代码。解决了包括 CROS 等问题。我发现对于这一个项目来说，前端并不不需要显示的将登录的 Token 在接口中指定并发送到后端，而是一种类似于浏览器自动携带的方式，然后由 Spring Boot 框架拦截并做鉴权，最开始我认为这就是一般开发的规范，但后面我发现似乎并非唯一的解决方案，而是一种可选项。因此整理了文档。
